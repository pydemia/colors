# Colors 고도화 구현 명세

기준: HEAD 60f06e3, COLOR_IMPROVEMENT_REVIEW.md, 사용자의 다중 입력색 요청.
현재 명세 버전: design-2026-10-04-b. 원래 검토 입력 a는 reviews/design-2026-10-04-a.md에 보존한다.

## 제품과 완료 기준

사용자가 의도·사용처·하나 이상의 색을 입력하고, 고정하거나 제한적으로
보정한 세 후보를 비교한 뒤 실제 사용 맥락을 조정·검증·내보낸다.
기존 웹/발행물/PowerPoint/편집기/터미널 역할과 저장 데이터를 유지한다.
현재 도메인 colors.pydemia.ai에서 실제 동작을 확인해야 완료다.

검토에서 바로잡은 사양이 원본 기획서의 과학적 단정에 우선한다.
광원 조작은 창작용 Warm/Cool 및 Green/Magenta 두 축이다. 물리적 CCT,
원단 측색, ICC 인쇄 결과, 원전 미확인 와다 팔레트라는 주장은 하지 않는다.
3D LUT는 전체 RGB 입력을 변환하는 별도 룩 함수로 생성한다.
Figma 플러그인 출시·유료 색표 데이터·원격 사진 검색은 이 웹앱 고도화와
별도 제품/데이터 취득이며 완료 주장에 포함하지 않는다.

## 화면과 상태 설계

기존 CREATE → REFINE → APPLY 흐름과 editorial 시각 체계를 유지한다.
CREATE는 콘셉트/사용자색/레시피에서 시작하며 고정은 기본 ON이다.
빠른 모드는 색과 의도만 노출하고 전문가 설정은 native details로 펼친다.
REFINE은 후보와 원색/추천색 비교, 컬러리스트 설정, 색좌표, colormap을
제공한다. APPLY는 역할·맥락·대비·출력으로 이어진다.

색 생성 설정은 초안이며 버튼으로 후보를 만들고, 후보 카드 선택 때만 현재
결과와 자동 파생 역할에 적용한다. 재추천만으로 현재 결과를 교체하지 않는다.
분석의 표색계·colormap 유형/혼합/위치와 장면·면적은 현재 프로젝트에 직접 저장한다.
고정/유연색과 피할 색이 모순이면 후보에 경고를 붙인다. 수동 역할 수정은
자동 파생과 분리해 재생성에서도 유지한다. 출력은 현재 보이는 프로젝트를
사용한다. 채택된 상태의 원본은 Project 한 곳이며, 미채택 후보와 생성 설정은
별도 임시 상태로 둔다. 현재 결과를 직접 편집하면 후보 선택 표시는 해제한다.

기본 의미 구조는 section/fieldset/label/button/select/details/table이다.
두 축은 키보드 가능한 range 두 개와 좌표 패드로 제공한다. 모든 제어에는
레이블을 붙이고 상태/오류는 live region으로 안내한다. 시안의 시각 효과는
실제 색값 및 대비 계산에서 분리한다. 760px 이하는 단일 열로 전환한다.

## 연산·데이터 명세

culori/React/Vite를 유지한다. 추천 엔진은 순수 함수로 분리한다.
앵커는 안정 ID, originalHex, fixedHex, locked, 보정 상한, t/positionLocked를 저장한다.
유연색을 재잠그면 fixedHex는 현재 색이며 원색과 차이를 계속 표시한다.
수치 연산은 OKLab/OKLCH, 최종 sRGB HEX의 실제 차이로 상한을 검증한다.
고정색은 생성의 입력 제약이며 결과 뒤 덮어쓰기로 맞추지 않는다.
유연색은 항상 originalHex에서 출발한다. 잠금 해제는 원색 기준을 초기화하지 않는다.
무채색의 hue는 조화 판단에서 제외한다. RGB 광량 합은 linear RGB에서
계산하고 평균과 별도 모델로 표시한다. 평균은 (1−t)A+tB, 광량 합은
그 값에 1+4t(1−t)를 곱하고 0~1로 제한한다. 감색은 A^(1−t)B^t 투과율
곱 근사이며 실제 안료의 분광 혼합을 대신하지 않는다.
색 방향 Warm/Cool은 조정 가능한 색에 창작 축 ±0.35를 더한다. 주변 채도는
모든 생성색에 적용하며 입력색의 고정/유연 보정 계약을 우선한다.
무채색 monochromatic에서는 자동 색 방향보다 무채색 유지가 우선한다.
사용자가 Warm/Tint 슬라이더를 직접 움직이면 명시적인 창작 보정으로 취급한다.

연속 colormap은 명시적 stop을 평가한다. CSV는 기본 256 표본과 모든
앵커 t의 합집합을 출력해 정확한 고정색을 포함한다. 팔레트와 연속 함수의
조건 검사 결과를 분리한다. 위치 모순·고정 명도 모순을 자동으로 숨기지 않는다.

schema2는 기존 swatches/roleSets를 유지하고 studio 및 sequence를 추가한다.
schema1의 색/역할 override는 그대로 이행한다. 저장 키는 기존 키를 유지해
과거 프로젝트를 찾아 마이그레이션한다. 최초 저장/삭제 전 원문을
colors.projects.v1.backup으로 보존한다. schema1에서 수동 여부가 불분명한
역할 연결은 userBinding으로 보존한다. 파생 역할만 자동으로 재계산한다.
표색계 editingSpace를 포함해 저장하며, 장면은 자체 swatches/roleSets/studio를
반드시 가져야 한다. 장면의 부모값 대체로 누락을 숨기지 않는다.
UI의 펼침 여부·분석 대상 색·원색/명도 표시와 미채택 초안은 일시적인 화면 상태다.

## 구현 순서와 검증

1. 명세 독립 검토와 지적 판정.
2. 색좌표/추천/보정/colormap 순수 함수 및 데이터 이행.
3. 입력/전문가 설정/분석/맥락/sequence와 역할 적용.
4. 출력 인코더 및 구조·정확한 색·표본·LUT 검증.
5. 구현 스냅샷 리뷰, 회귀 테스트, 실제 데스크톱/모바일 UI 검증.
6. Vercel 프로덕션 배포 및 실제 도메인의 생성·복원·출력 확인.

픽셀 일치보다 관측 가능한 기능과 데이터 불변 조건을 검증한다.
검증하지 않은 실제 Adobe/Office/영상 도구 가져오기까지 호환성을 단정하지 않는다.
