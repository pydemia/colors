# Colors 첫 공개 화면 와이어프레임

상태: 화면 구조 제안 · 2026-09-30 첫 공개 범위 반영

이 문서는 [제품 기획](PRODUCT_PLAN.md)의 화면 흐름 초안이다. 현재 구현과
검증 결과는 [RELEASE_SCOPE.md](RELEASE_SCOPE.md)와 QA 보고서에 기록한다.
사진 업로드·다운로드·저장소·검색·추출은 이번 릴리스에서 `준비 중`이다.

## 화면 지도

```text
시작 ── 콘셉트 ─┐
     └ 기준색 ───┼─→ 후보 비교·원본 팔레트 ─→ 사용처 역할·시안 ─→ 저장·내보내기
       사진(준비 중)             ↑                     │
                              └──── 색·역할 수정 ────────┘
```

첫 공개는 비회원 흐름이다. 사진 업로드·검색·추출·다운로드, 계정, 공개 링크,
갤러리는 후속 단계 항목으로 표시하되 첫 공개 화면에 동작하는 버튼처럼
보이지 않게 한다. 첫 방문에는 예제 팔레트를 탐색할 수 있으나 저장 데이터와
혼동하지 않도록 `예제` 표시를 붙인다.

## 1. 시작 화면

```text
┌ Colors ────────────────────────────── [저장된 프로젝트] ┐
│ 나에게 맞는 색 조합을 만들어 보세요                         │
│ [콘셉트로 시작] [기준색으로 시작] [사진 · 준비 중]           │
│                                                       │
│ 선택한 경로의 입력 패널                                 │
│ 콘셉트: 사용처 / 분위기 태그 / 색 방향 / 밝기 / 채도         │
│         피할 색 / 자유 메모(생성에는 미반영)                │
│ 기준색: HEX [#______] / 색 선택기 / 조화 유형              │
│ 사진: 기능 준비 중 안내와 비활성 메뉴                      │
│                                                       │
│                         [후보 만들기]                  │
└───────────────────────────────────────────────────────┘
```

- 경로를 바꿀 때 이미 입력한 값은 그 경로 안에서 유지한다.
- 기준색은 유효한 `#RRGGBB`만 받는다. 오류는 입력 바로 옆에 글로
  설명하고 유효하지 않으면 생성 버튼을 비활성화한다.
- 사진 메뉴에서는 파일 선택기를 열지 않는다. 실제 업로드·추출 흐름은
  파일 저장 정책을 결정한 뒤 별도 단계에서 설계·구현한다.

## 2. 후보 비교·원본 팔레트

```text
┌ Colors / 편집 ───────────── [프로젝트 JSON 저장] [내보내기] ┐
│ 시작 입력 요약                 [입력 수정] [후보 다시 만들기] │
├ 후보 1 ───────── 후보 2 ───────── 후보 3 ─────────────────┤
│ [5색 띠]        [5색 띠]        [5색 띠]                  │
│ [선택]          [선택]          [선택]                    │
├ 선택한 원본 팔레트 ───────────────────────────────────────┤
│ ① #336699 [잠김] [입력색]      [색 편집] [순서 이동]       │
│ ② #F7FAFC [잠그기] [생성색]    [색 편집] [순서 이동]       │
│ ③ ...                                                 │
│ 사진 경로: [자동 추출] / [직접 선택 (x,y)] 출처 배지       │
├ 사용처: [웹] [발행물] [PowerPoint] [편집기] [터미널] ────┤
│                                      [역할 배정으로]       │
└───────────────────────────────────────────────────────┘
```

- 후보를 고르면 원본 팔레트에 복사한다. 잠긴 색을 가진 상태에서
  `후보 다시 만들기`를 눌러도 그 HEX와 잠금은 유지한다.
- 각 색은 HEX·출처 이름·잠금 상태를 문자와 아이콘으로 함께 표시한다.
  순서 변경은 swatch `id`와 역할 참조를 바꾸지 않는다.
- 사진에서는 이미지 위 선택점과 `직접 선택` 배지를 함께 보여 준다.
  저장 후 원본 이미지가 없으면 점 편집은 `원본 사진 다시 선택` 안내로
  바뀐다. 추출된 HEX와 출처 메타데이터는 남는다.
- 처음 선택한 후보를 바꿀 때 이미 편집한 원본색·역할값이 있다면
  교체 범위를 묻고, 잠긴 색과 수동 덮어쓰기는 기본으로 보존한다.

## 3. 사용처 역할·시안

```text
┌ 원본색 5개: ① ② ③ ④ ⑤ ───── [후보 비교로] ───────────────┐
│ [웹] [발행물] [PowerPoint] [편집기] [터미널]             │
├ 역할 목록 (왼쪽) ──────────── 시안 (오른쪽) ──────────────┤
│ 배경  ② #F7FAFC [변경]       실제 역할색을 쓴 예제 화면   │
│ 본문  ③ #1E293B [변경]       선택한 역할의 위치 강조      │
│ 주색  ① #336699 [변경]                                  │
│ ...                         [대비 계산값·기준·통과]      │
│                             [대비 계산값·기준·미달]      │
│                             [수정안 보기]               │
└───────────────────────────────────────────────────────┘
```

- 역할 변경 메뉴는 `원본색 선택`, `이 역할만 색 변경`, `원본색 사용`을
  구분한다. `이 역할만 색 변경`은 덮어쓰기로 저장하고 원본 팔레트는
  바꾸지 않는다. 잠긴 색을 바꾸려는 동작에는 잠금 해제가 필요하다.
- 수정안은 변경 전후 HEX와 대비를 나란히 보여 준다. 사용자가
  `적용`을 누르기 전에는 프로젝트를 바꾸지 않는다. 잠긴 색을
  수정해야만 기준에 도달하는 경우에는 다른 역할의 수정안을 제시한다.
- 웹 탭은 헤더·버튼·링크·상태 표시, 발행물은 표지·본문,
  PowerPoint는 제목·본문·차트 6강조색을 포함한 화면 시안을 둔다.
- 편집기 탭은 같은 코드의 최소 두 언어 예제를 보여 주고 VS Code,
  JetBrains, Vim의 적용 대상 역할을 설명한다. 터미널 탭은 기본
  전경·배경·커서·선택과 ANSI 16색 표를 보여 준다. 이 시안은
  실제 프로그램의 렌더링 검증 결과가 아니라 역할 배치의 모사다.
- 대비 경고에는 적용된 전경·배경 역할, 수치, 기준을 같이 표시한다.
  미달 상태를 색만으로 전달하지 않는다.

## 4. 저장·내보내기

```text
┌ 저장·내보내기 ────────────────────────────────────────────┐
│ 프로젝트: [이 기기에 저장] [JSON 백업] [JSON 가져오기]      │
│ 화면용:    [CSS 변수]                                     │
│ 프로그램 파일: PowerPoint / VS Code / JetBrains / Vim /   │
│   iTerm2 / Windows Terminal / PuTTY · 검증 후 제공 예정    │
│                                                       │
│ 선택한 형식의 포함 역할·적용 방법·검증 상태               │
│ [파일 받기 또는 복사]                                     │
└───────────────────────────────────────────────────────┘
```

- 실제 적용 검증 전에는 모든 프로그램별 파일과 설정 조각을
  `검증 대기`로 표시하고 정식 다운로드 버튼을 켜지 않는다.
- 프로그램별 전용 파일은 모호한 `지원` 배지 대신 계획 상태와
  필요한 검증을 명시한다. 기존 사용자 설정을 통째로 덮어쓰는
  적용 절차는 제공하지 않는다.
- 기기 안 저장은 브라우저 데이터 삭제 시 사라질 수 있음을
  설명하고 JSON 백업을 함께 권한다. JSON 가져오기는 기존 프로젝트를
  덮어쓰기 전에 미리보기와 오류 확인을 거친다.

## 작은 화면과 입력 접근성

작은 화면에서는 후보 카드, 원본색, 역할 목록, 시안을 한 열로 쌓고
현재 사용처 탭을 상단에 유지한다. 원본색과 역할 목록은 접기보다
각 행에 HEX·출처·잠금을 보이게 한다. 선택점 조정에는 이미지 클릭
외에 좌표 이동 또는 색 입력 대안을 제공한다. 모든 버튼은 키보드로
이동·실행할 수 있어야 하며, 후보·잠금·대비 상태는 문자로도 읽힌다.

## 검토 시나리오

1. `#336699`를 기준색으로 입력해 잠근 뒤 후보를 다시 만들고,
   웹 `primary`와 터미널 `blue`에 같은 원본색을 배정한다.
2. 웹 `text`만 별도 HEX로 바꾸고 원본 팔레트·PowerPoint·터미널
   역할이 그대로인지 확인한다.
3. 사진 업로드·검색·다운로드가 `준비 중`으로 표시되고 파일 선택기나
   외부 요청을 시작하지 않는지 확인한다.
4. 대비 미달 조합에서 수정안을 보되 취소하고, 다시 적용해
   변경된 역할만 확인한다.

위 시나리오는 앞으로 수행할 사용성·구현 검증 절차다. 실행 결과는 없다.
